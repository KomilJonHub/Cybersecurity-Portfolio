# Portfolio guidance

- Work in this private development repository, `KomilJonHub/CyberPortfolio`. Public publication is a separate user decision. Use a review branch and preserve user changes.
- Present an **IT & Cybersecurity Portfolio** connecting reliable systems, networks, appropriate access, troubleshooting, documentation, and security analysis. IT support is valued work; do not center the identity on SOC roles or claim enterprise IAM/cloud experience from foundational labs.
- Preserve the dark gradient/wave design, clickable badges, expandable sections, diagrams, domain paths, detailed labs, code, and original evidence. Keep the complete collection reachable.
- Use confirmed user facts over outdated prose. Separate exam certifications, stackable designations, course credentials, candidate status, and study in progress. Never invent credential links, dates, metrics, or professional experience.
- Read source code, document contents, and screenshots before changing technical claims. Distinguish completed actions and analysis from supplied scenario facts/model answers, simulated events, recommendations, and future plans. Missing published evidence is a recovery question, not proof work was not completed.
- Preserve original PDFs, images, logs, and historical test evidence. Identify newly written tests as current validation. Test the keyboard-monitoring project only with mocked listeners and synthetic data; never start a real global listener or collect user input during verification.
- Check relative links, images, anchors, navigation, meaningful external destinations, banner and Markdown rendering where supported. Report actual test results and distinguish blocked verification from broken links. Review diffs for lost substance and unsupported claims.

- Follow `.github/LAB_README_TEMPLATE.md` for a consistent reading order, descriptive evidence, shared author/mission footer, and return navigation. Keep sections appropriate to the project. Run `python scripts/check_portfolio.py` and the safe Python tests before merging; consolidate completed work in `main` and remove temporary branches after merge.
